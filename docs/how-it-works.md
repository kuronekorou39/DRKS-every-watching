# しくみ

サーバーは持たない。GitHub Actions が各 API から配信状況を取得して `data` ブランチの `history.json` に足し、
GitHub Pages がそれを静的サイトとして公開する。

## 取得（`collect`）

- 10分おきに取得し、記録に変化があったときだけ `data` ブランチへコミットして、`deploy` を起動する
- Actions の cron は混雑で数時間あくことがある（実測で 2〜5 時間おき）。そこで1回の実行の中で取得を繰り返し（約5時間半）、
  終わる直前に自分で次の実行を起動してつなぐ。cron（毎時17分・47分）は、つながりが切れたときに起こし直す保険
- 取得の間隔は `.github/workflows/collect.yml` の `INTERVAL_SECONDS`
- 繰り返しの各回で最新の `main` を取り直すので、設定ファイルの変更は次の回（10分以内）から効く
- 取得が6回つづけて失敗すると、実行を失敗にする（GitHub から通知メールが届く）

| 配信先 | 取り方 | 過去の配信 |
|---|---|---|
| Twitch | アーカイブで正確な開始・終了を取り、ライブ状態のポーリングで補う | アーカイブが残っている分は初回に埋まる |
| YouTube | アップロード一覧の新しい50本から、ライブだったものの実際の時刻を取る | その50本に入っている分 |
| Kick | 配信中かどうかのポーリングだけ（公開 API に過去分がない） | 埋まらない。[手で足す](config.md#manualjson) |

- 一度記録した配信は、アーカイブが消えても残る（サムネイルは消える）
- `channels.json` の書き間違いでは、記録を書き換えずにエラーで止まる
- API の不調や Secrets の未設定では、そのプラットフォームだけ飛ばして前回までの記録を残す（Actions に警告が出る）

## 公開（`deploy`）

`main` への push と、`collect` からの起動で走る。画面のファイルと `data` ブランチの `history.json` を合わせて Pages に公開する。
push のときはテストも走らせ、`collect` が止まっていれば起こす。

## 画面

ビルドなしの素の HTML・ES Modules・CSS。`history.json` を5分おきに読み直し、現在時刻の線と配信中のバーは1分ごとに進める。
開きっぱなしで日付が変わると、今日までを表示していた場合に限り、表示範囲を1日進める。

| 場所 | 中身 |
|---|---|
| `index.html` / `app.mjs` / `style.css` | 画面 |
| `lib/core.mjs` | 取得スクリプトと画面で共有するロジック（マージ、区間の結合、日時の整形） |
| `scripts/fetch.mjs` / `scripts/platforms/` | 取得。プラットフォームごとに1ファイル |
| `scripts/kick-import.mjs` | Kick の過去の配信を `manual.json` に取り込む |
| `.github/workflows/collect.yml` / `deploy.yml` / `test.yml` | 取得 / 公開 / 画面のテスト |
| `test/` / `e2e/` | 共通ロジックのテスト / 画面のテスト（[詳しくは](setup.md#テスト)） |

## 注意

- 開始時刻は API の値なので正確。アーカイブが残らない配信は、終了時刻が最大10分ほどずれる
- YouTube はプレミア公開もライブとして拾うことがある（API で区別できない）
- 実行の切り替わり（約5時間半ごと）で、取得が数分あくことがある
- リポジトリに60日間動きがないと cron は自動停止する。止まっていたら Actions タブから再有効化する
